# Учебное руководство RustML

Обновлено: 2026-10-11. Работающий публичный синтаксис — в [README.md](README.md),
источники инженерных решений — в [PLAN.md](PLAN.md). Здесь объясняется математика и смысл
реализации; копии целых исходных файлов заменены ссылками, чтобы они не расходились с кодом.

## 1. Тензор и его форма

Тензор в этой библиотеке — многомерный массив. Скаляр имеет форму `[]` и один элемент,
вектор `[3]` — три элемента, матрица `[2,3]` — две строки по три элемента.
Форма `[0,3]` означает пустой массив, а не скаляр.

`Tensor<T>` обобщён по типу числа: Rust проверяет dtype при компиляции, но размеры осей
динамические. Поэтому `[2,3] @ [4,2]` — ошибка времени исполнения, возвращаемая в Result.
В отличие от C, `Result<T, RustMLError>` явно требует обработать успешное значение или ошибку;
`?` передаёт ошибку вызывающей функции.

Реализация: [tensor.rs](rustml-tensor/src/tensor.rs), [shape.rs](rustml-tensor/src/shape.rs).
Данные хранятся в `ndarray::ArrayD`, форма — список размеров осей.
`checked_numel()` проверяет переполнение; нулевая ось даёт нулевое число элементов.
Для реального массива проверяются также пределы layout ndarray и размера памяти.

Для недоверенных размеров используйте `try_zeros`/`try_ones`/`from_vec`.
Удобные `zeros`/`ones` документированно паникуют при невозможности создания массива.
Это не обещание восстановиться после любого системного недостатка памяти.

## 2. Поэлементные операции и broadcasting

Поэлементное сложение: `[1,2] + [3,4] = [4,6]`.
Broadcasting позволяет использовать один элемент несколько раз без ручного создания копий входа.
Например, `[1,2,3] + 10 = [11,12,13]`.

Оси сравниваются справа налево. Пара совместима, когда размеры равны или один из них равен 1.
Недостающая ведущая ось считается единичной.

| Формы | Результат |
|---|---|
| `[2,3]` и `[3]` | `[2,3]` |
| `[2,1]` и `[1,3]` | `[2,3]` |
| `[0,3]` и `[1,3]` | `[0,3]` |
| `[2,3]` и `[2]` | Ошибка |

Размер результата нельзя выбирать простым `max`: `0` вместе с `1` должно давать `0`.
Отсутствующую ось нельзя получать вычитанием из unsigned индекса: под нулём происходит underflow.
Текущая реализация безопасно читает размеры с конца.

Операторы используют broadcast views ndarray и выделяют новый результат.
Ссылка `&Tensor` не делает результат автоматически zero-copy. `view()` заимствует память;
`clone()` Tensor копирует массив. `into_data()` переносит владение без копирования.

Числовой контракт: для целых `+`, `-`, `*`, `/` и накопление проверяются; переполнение,
деление на ноль и `MIN / -1` дают NumericalError. Для f32/f64 сохраняется IEEE-754:
NaN и Inf распространяются как числа, а не превращаются автоматически в Result::Err.

Реализация и регрессии: [ops.rs](rustml-tensor/src/ops.rs), [dtype.rs](rustml-core/src/dtype.rs).

## 3. Матрицы

Для `A[M,K]` и `B[K,N]` произведение `C[M,N]` вычисляется так:

```text
C[i,j] = sum_k A[i,k] * B[k,j]
[[1,2],[3,4]] @ [[5,6],[7,8]] = [[19,22],[43,50]]
```

Учебный matmul использует три цикла. Общая работа пропорциональна `M*K*N`.
При `K=0` сумма пуста и каждый элемент результата равен нулю.
`transpose()` для 2D меняет строки и столбцы: `Aᵀ[j,i] = A[i,j]`.
Обе операции сейчас выполняются на CPU; batched matmul не реализован.

Для будущего autograd matmul потребуются `dA = grad @ Bᵀ` и `dB = Aᵀ @ grad`.
Эти формулы здесь — следующая учебная задача, не описание уже существующего оператора Variable.

## 4. Производная, градиент и правило цепочки

Производная показывает локальную чувствительность результата к изменению входа.
Для `y=x²` имеем `dy/dx=2x`: при `x=2` маленькое увеличение x на 0.001 увеличивает y примерно на 0.004.
Градиент содержит такие производные по всем элементам входного тензора.

Правило цепочки: если `u=f(x)`, `y=g(u)`, то `dy/dx = (dy/du)*(du/dx)`.
Для `u=x*x`, `y=u*x` при x=2:

```text
u = 4, y = 8
через прямое ребро x -> y: вклад 4
через u: dy/du = 2, du/dx = 4, вклад 8
общий dy/dx = 4 + 8 = 12
```

Одна переменная может участвовать в нескольких путях. Вклады нужно складывать.
Локальные правила: для `a+b` производные по a и b равны 1;
для `a*b` производная по a равна b, а по b — a.

## 5. Forward, граф и backward

Forward вычисляет значение и сохраняет входы операции, нужные для производных.
Граф направленный и без циклов: новая операция ссылается только на существующие входы.
`Variable<f32/f64>` хранит значение, признак tracking, операцию и накопленный градиент.
Целочисленные Variable запрещены типами; integer Tensor по-прежнему можно использовать для данных.

В Rust `Arc` — владение с общим счётчиком ссылок. Это похоже на reference counting в C,
но компилятор контролирует доступ к объекту. `Variable::clone()` увеличивает счётчик,
разделяя одно значение и один градиент; он не создаёт независимый параметр.
`RwLock` защищает градиент, который меняется через неизменяемую ссылку. Значения forward остаются неизменными.

Текущий backward выполняет три действия:

1. Итеративно находит уникальные узлы и порядок зависимостей.
2. Идёт от результата к входам, суммируя входящие вклады для каждого узла.
3. Записывает накопленный градиент и распространяет только новый вклад данного вызова.

Это предотвращает экспоненциальное повторение работы для цепочки `u = u + u`.
Старые градиенты от предыдущего backward не запускаются по графу повторно.
Сам обход не рекурсивен; освобождение чрезвычайно глубокой цепочки Arc всё ещё может быть рекурсивным.
Не следует считать такую цепочку неограниченно устойчивой к глубине.

Реализация: [variable.rs](rustml-autograd/src/variable.rs), [graph.rs](rustml-autograd/src/graph.rs).
Закрытый enum операций достаточен для нынешних Add/Mul; публичный framework для произвольных backend не нужен.

## 6. Broadcasting в обратном проходе

Если bias формы `[3]` прибавили к двум строкам `[2,3]`, каждый элемент bias использован два раза.
После суммы всех выходов его градиент `[2,2,2]`, а не матрица `[2,3]`.
Поэтому локальная производная сворачивается суммой по расширенным осям до формы исходного входа.

`Tensor::sum_to_shape` выполняет именно эту операцию. Сумма по пустой оси равна нулю.
Для `[0,3] + [1,3]` градиент первого входа пуст, а градиент второго имеет форму `[1,3]` и заполнен нулями.
Это проверяется для Add и Mul в [gradients.rs](rustml-autograd/tests/gradients.rs).

## 7. Начальный градиент и повторные вызовы

Для скаляра backward начинает с 1. Для тензора выбран явный контракт:
`backward()` вычисляет производную суммы элементов, то есть начинает с тензора единиц.
`backward_with_grad(seed)` позволяет задать другие веса выходов; shape должна совпадать точно.
Это vector-Jacobian product: для каждого входа суммируются взвешенные производные выходов.

Два вызова backward на одном графе добавляют два вклада. `zero_grad()` очищает только указанную
Variable, включая её aliases. Очистка листа не очищает весь граф, но сохранённые промежуточные
градиенты не вмешиваются в новый проход: для него используется отдельное накопление.

## 8. Изменение параметров

Backward вычисляет производные, но не обновляет веса. Шаг SGD имеет формулу:

```text
new_weight = old_weight - learning_rate * gradient
```

`data_mut()` разрешён только уникальному листу: все clones и результаты, удерживающие этот лист,
нужно сначала освободить. Это действует и для констант, сохранённых операциями.
Отказ возвращает ошибку и сохраняет данные/градиент. Успешный доступ очищает старый градиент.
Следовательно градиент нужно прочитать до получения mutable доступа.
`set_requires_grad()` также возвращает Result и требует уникального листа.

`detach()` создаёт независимую копию без tracking. Это проще полной системы версий in-place операций
и предотвращает применение старого графа к изменённым данным. Следующий training step строит новый граф.
Concurrent backward вместе с zero_grad/мутацией не является поддерживаемым training-контрактом.

## 9. Независимая проверка математики

Для гладкой функции центральная конечная разность:

```text
numerical_gradient = (f(x + epsilon) - f(x - epsilon)) / (2 * epsilon)
```

Используем f64 и небольшие значения. Слишком маленькое epsilon усиливает ошибку округления,
слишком большое — ошибку приближения. В тесте берём epsilon 1e-6 и сравниваем с относительным допуском.
Тестовая формула вычисляется отдельно от autograd, чтобы не повторить ошибку реализации.

Одной конечной разности недостаточно: отдельно проверяются общие ветки, нулевые оси, точные формы,
повторные проходы, aliases и отклонённые мутации. В точках излома будущей ReLU производная
не определяется единственным гладким пределом; такую точку нельзя использовать как обычный gradcheck.

## 10. Следующая учебная задача

Связать differentiable matmul, MSE и SGD в одном Linear-слое, затем обучить `y=2x+1`.
Сначала добиться верных градиентов и уменьшения loss, потом обсуждать скорость.
GPU, сложные NN-архитектуры и production-ready статус текущей Rust-библиотеки не заявлены.

Интерактивный веб-учебник разрабатывается отдельно и может показывать архитектуры,
которые ещё не реализованы в RustML. Его демонстрационные вычисления не доказывают наличие этих API в Rust.
