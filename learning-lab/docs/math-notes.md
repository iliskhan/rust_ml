# Математика интерактивного учебника

Дата сверки источников: 11 октября 2026. Модуль `src/math.ts` считает в JavaScript `number` (IEEE 754 binary64). Это исполняемые учебные формулы, а не вызов RustML или PyTorch. Результаты проверяются ручными примерами и центральными разностями в `tests/math.test.ts`.

## Прямой проход и потери

`linear` принимает `X[batch,in]`, `W[out,in]`, `b[out]` и возвращает `Y[batch,out]`: `Yᵢⱼ = Σₖ Xᵢₖ Wⱼₖ + bⱼ`. Формы проверяются; broadcasting отсутствует.

Для `z` активации и производные по **входу**:

- ReLU: `max(0,z)`; производная `1` при `z>0`, иначе `0`. В нуле производная математически не определена; модуль выбирает `0`.
- sigmoid: `σ(z)=1/(1+exp(-z))`; `σ′=σ(1-σ)`. Для отрицательного `z` используется равносильная форма `exp(z)/(1+exp(z))`.
- tanh: `tanh(z)`; производная `1-tanh²(z)`.

`mse`: `L = Σᵢ(predᵢ-targetᵢ)²/n`, `∂L/∂predᵢ = 2(predᵢ-targetᵢ)/n`. `terms` содержит квадраты ошибок до усреднения. Здесь **нет** множителя `1/2`; такое усреднение соответствует [MSELoss с reduction=mean](https://docs.pytorch.org/docs/stable/generated/torch.nn.MSELoss.html).

Вероятностная BCE: `L=-y ln(p)-(1-y)ln(1-p)`, `∂L/∂p=-y/p+(1-y)/(1-p)`. Аргументы `p,y∈[0,1]`. Члены с нулевым весом пропускаются, чтобы избежать `0·ln(0)`. Ошибочный уверенный ответ на границе имеет бесконечную потерю и градиент. Искусственного clamp нет; это не копия численного поведения PyTorch BCELoss.

BCE-logits: `L=max(z,0)-zy+ln(1+exp(-|z|))`, `∂L/∂z=σ(z)-y`. `Math.log1p` сохраняет малые добавки. Объединение sigmoid и BCE устраняет вычисление `ln(0)` после округления вероятности — принцип из [BCEWithLogitsLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.BCEWithLogitsLoss.html).

## Общий узел и проверка градиента

Фиксированный граф: `q=xw`, `p=q²+q`, `L=(p-target)²/2`. Пусть `δ=p-target`. Вклад квадрата в `∂L/∂q` равен `2qδ`, вклад прямой ветви равен `δ`; они **складываются**. Затем `∂L/∂x=(2q+1)δw`, `∂L/∂w=(2q+1)δx`. При `x=2,w=3,target=2`: `q=6,p=42,L=800,∂L/∂q=520`. Это частный пример обратного прохода по правилу цепочки, описанного в [Autograd mechanics](https://docs.pytorch.org/docs/stable/notes/autograd).

`finiteDifference` оценивает каждый компонент как `(f(θ+h eᵢ)-f(θ-h eᵢ))/(2h)`, по умолчанию `h=1e-5`. Этот независимый численный подход применяет и [PyTorch gradcheck](https://docs.pytorch.org/docs/stable/notes/gradcheck.html). Слишком маленький `h` увеличивает ошибку округления, слишком большой — ошибку приближения; в изломе ReLU обычная проверка производной неприменима.

## Оптимизация

Обновления возвращают новое состояние `{params,m,v,step}`. Начальные `m,v` нулевые. При смене алгоритма или β следует создавать новое состояние.

SGD: `θₜ=θₜ₋₁-lr·gₜ`. Momentum: `mₜ=μmₜ₋₁+gₜ`, `θₜ=θₜ₋₁-lr·mₜ`; это соглашение без dampening, Nesterov и weight decay из [SGD](https://docs.pytorch.org/docs/stable/generated/torch.optim.SGD.html).

Adam: `mₜ=β₁mₜ₋₁+(1-β₁)gₜ`, `vₜ=β₂vₜ₋₁+(1-β₂)gₜ²`; `m̂=mₜ/(1-β₁ᵗ)`, `v̂=vₜ/(1-β₂ᵗ)`, `θₜ=θₜ₋₁-lr·m̂/(√v̂+ε)`. `ε` находится **вне** корня. Сверено с [Adam в PyTorch](https://docs.pytorch.org/docs/stable/generated/torch.optim.Adam.html) и [Kingma & Ba, Adam](https://arxiv.org/abs/1412.6980). Defaults: `lr=.03,μ=.9,β₁=.9,β₂=.999,ε=1e-8`; учебный `lr` не является универсальной рекомендацией.

Поверхность для сравнения: `f(x,y)=(x²+8y²)/2`, `∇f=(x,8y)`. Результаты сравнения относятся к этой функции и выбранным настройкам; превосходство алгоритма в других задачах из них не следует.

## XOR и ограничения

Сеть имеет 17 параметров: `W₁[4,2]` (индексы 0–7), `b₁[4]` (8–11), `W₂[1,4]` (12–15), `b₂[1]` (16). Скрытый слой — tanh; выход — logit. Обучение усредняет BCE-logits по всем четырем парам XOR. `predictNetwork` применяет sigmoid только для показанной вероятности. Обратный проход выведен вручную; тест сравнивает все 17 компонентов с численными производными.

`createNetwork(seed)` использует локальный детерминированный генератор: веса в `[-1,1)`, скрытые bias в `[-.1,.1)`, выходной bias нулевой. Seed приводится к unsigned 32-bit. В тесте заложено обучение seed `1,7,42,1337` Adam за 3000 шагов с `lr=.03`: требуется BCE < .02 и четыре верных ответа при пороге .5. Успешность любого seed или любой скорости обучения не гарантируется.

Модуль ограничен малыми учебными массивами и одним фиксированным графом; он не строит универсальный autodiff engine. Конечные входы экстремального масштаба могут дать переполнение в умножении/сумме. При больших logit sigmoid округляется к 0 или 1, а очень малые градиенты исчезают. Нулевые параметры XOR создают симметрию с нулевым градиентом; seeded инициализация нужна для ее нарушения. При расходящемся обучении следует уменьшить `lr` или сбросить состояние. Успешные unit tests не проверяют внешний вид интерфейса.
